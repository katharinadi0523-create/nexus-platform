# 第三方插件服务供给与管理：竞品调研

**日期：** 2026-11-18

**研究问题：** B 端 AI 产品如何提供第三方服务、配置连接与凭证、授权使用、控制工具动作，以及管理变更和下线？

本报告依据各产品的官方文档。不同产品的组织、工作空间和环境不是同一概念；比较的是职责与流程，不直接套用它们的权限层级。文档说明也不等于本轮登录竞品后台逐屏实测。

## 1. 产品对照

| 产品 | 第三方能力如何提供 | 管理员做什么 | 用户/开发者做什么 | 凭证与使用范围 |
|---|---|---|---|---|
| ChatGPT Business / Enterprise | 管理后台同时覆盖平台提供的插件、所含 App，以及自定义 MCP 连接。插件可以打包技能和 App，安装与底层 App 访问分开。 | 设置插件可安装、默认安装或禁用；控制 App 访问角色、可执行动作、调用确认策略。自定义 MCP 先私下连接和测试，再由管理员发布。 | 安装获准的插件；需要个人供应商账号的 App 由用户自行连接。获授权成员可创建并测试自定义 MCP。 | 可使用个人供应商账号，也可使用管理员管理的连接；插件已安装仍可能因底层 App 禁用而不可调用。来源：[管理员控制](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-for-plugins-and-apps)、[自定义 MCP](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)。 |
| 飞书 Aily | MCP 市场收录 Aily 内创建并发布的 MCP，也接纳 Anycross、aPaaS 等来源。 | 在企业管理后台的 MCP 服务管理页上下架。成员发布后默认上架；管理员下架会通知创建者并阻断 Aily 内调用。 | 只查看和调用自己有使用权限的 MCP。 | 官方页面聚焦市场治理，未说明预置第三方付费 Key 的所有者、计费归属和凭证轮换，不能据此推断这些能力。来源：[MCP 服务管理](https://aily.feishu.cn/hc/1u7kleqg_yukaniuj)。 |
| WorkBuddy Enterprise | 企业控制台的 AI 资源管理提供官方内置及管理员自建连接器；连接器封装认证、MCP 服务端、工具过滤等。 | 创建、启停、按部门/成员设可见范围，并可设置成员自建连接器策略；查看连接次数与调用次数。 | 客户端成员使用管理员下发的连接器，也可在策略允许时创建个人连接器；某些认证方式需要用户提供 Key 或账号。 | 支持 OAuth 2.0、MCP OAuth 2.1、API Key 和自建应用免授权。可见范围与启用状态独立，二者共同决定可用性。来源：[连接器管理](https://cloud.tencent.com/document/product/1831/134453)。 |
| Microsoft Copilot Studio | 预置连接器可作为智能体工具；也可自建连接器。智能体有独立的 Connection Settings，可看到各连接状态和依赖。 | 环境管理员可限制构建者凭证模式，避免构建者账号被使用者共享；通过环境策略控制连接。 | 构建者添加工具；默认由最终用户用自己的服务账号建立连接，也可以在允许时使用构建者提供的连接。 | “由谁提供凭证”是明确的身份选择。连接可能处于已连接、未连接、停用、过期、陈旧等状态。来源：[连接器工具](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-connectors)、[连接管理](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-connections)、[凭证策略](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-no-maker-authentication)。 |
| Claude for Work | 提供预建及远程 MCP 连接器；Team/Enterprise 组织 Owner 可配置自定义连接器。 | Owner/Primary Owner 启用组织连接器。 | 用户在组织连接器可用后自行连接并启用，用自己在第三方服务中的权限访问。 | 组织准入与用户账号授权分开；适合用户身份明确的 SaaS 数据服务。来源：[Remote MCP 连接器](https://support.anthropic.com/en/articles/11175166-about-custom-integrations-using-remote-mcp)。 |

## 2. 五个值得借鉴的设计规律

### 2.1 服务可发现、安装、连接、可调用是不同状态

ChatGPT 明确区分插件安装与底层 App 访问；WorkBuddy 把启用和可见范围拆开；Copilot Studio 还显示连接的过期与失效状态。因此 AF 需要分别表示：目录上架、组织/个人连接是否有效、项目/workspace 是否获授权、当前用户/智能体是否可调用。[ChatGPT 管理员控制](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-for-plugins-and-apps)、[WorkBuddy 连接器管理](https://cloud.tencent.com/document/product/1831/134453)、[Copilot Studio 连接管理](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-connections)。

### 2.2 凭证模式由服务决定，至少有三种

| 模式 | 适用场景 | 凭证所有者与费用 | 用户体验 |
|---|---|---|---|
| 组织共享连接 | 企业统一采购的搜索、OCR 等按组织账户计费的服务 | 组织持有供应商 Key、承担费用 | 管理员配置一次，获授权的项目/workspace 使用 |
| 用户委托连接 | GitHub、飞书文档等需遵守用户在源系统权限的服务 | 用户授权个人账号；费用可能由服务套餐或企业账户承担，需按供应商定义 | 管理员准入后，用户本人 OAuth 连接 |
| 个人自带连接 | 演示、测试或个人自费的服务 | 用户持有 Key 并承担费用 | 只在个人 Claw 范围使用，不跟随发布 |

WorkBuddy 覆盖多种认证方式，Claude 采用组织准入后用户个人连接，Copilot Studio 默认使用最终用户凭证，并可限制构建者凭证。由此推论，AF 的“预置服务”不能统一设计成管理员填一份共享 Key。[WorkBuddy](https://cloud.tencent.com/document/product/1831/134453)、[Claude](https://support.anthropic.com/en/articles/11175166-about-custom-integrations-using-remote-mcp)、[Copilot Studio](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-connectors)。

### 2.3 开发与治理可以共用目录，但权限独立

ChatGPT 把平台插件和自定义 MCP 放在同一管理员产品域，却将创建/测试、发布、安装、App 使用与动作权限拆开。Aily 保留成员发布入口，同时允许企业管理员下架和阻断调用。对 AF 的启发是：组件广场可统一发现；现有插件/MCP 管理保留开发者的资源生命周期；基础管控新增预置服务准入、连接和授权。无需复制两个完全独立的广场。[ChatGPT 自定义 MCP](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)、[Aily MCP 管理](https://aily.feishu.cn/hc/1u7kleqg_yukaniuj)。

### 2.4 工具变更与高风险动作需要单独管

ChatGPT 管理员可单独控制 App 动作；自定义 MCP 更新工具列表时，新动作默认关闭，并展示现有动作变化。Copilot Studio 说明共享构建者凭证可能让使用者获得构建者才有的数据或能力，因此可按环境限制此模式。AF 至少要在预置服务更新工具集时提示变更，并阻止新增工具自动获得原授权；写入/外发动作与只读调用可分开控制。[ChatGPT 管理员控制](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-for-plugins-and-apps)、[ChatGPT 自定义 MCP](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)、[Copilot Studio 凭证策略](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-no-maker-authentication)。

### 2.5 停用、下架、失效影响运行时

Aily 管理员下架会阻断后续调用并通知创建者；WorkBuddy 将连接器启停与成员可见性分别控制；Copilot Studio 区分失效、过期和停用。AF 不应把 Key 失效等同于目录下架。停用连接时应显示受影响的智能体、任务和工作空间，并保证新调用立即被阻断。[Aily](https://aily.feishu.cn/hc/1u7kleqg_yukaniuj)、[WorkBuddy](https://cloud.tencent.com/document/product/1831/134453)、[Copilot Studio](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-connections)。

## 3. 对现有 AF 方案的具体调整

1. **服务定义增加认证策略**：声明支持组织共享、用户委托、个人自带中的哪些模式；同一服务可支持多种模式，但每次调用必须确定使用哪一种。
2. **组织管理页先管准入，再管连接**：组织管理员决定是否允许该服务及个人连接；需要组织共享模式时，再配置组织 Key 并授权选定项目/workspace。用户委托模式只做组织准入，账号由用户本人连接。
3. **组件广场增加来源与可用性**：展示平台预置、自建 MCP/OpenAPI，以及“可添加、待组织开通、需本人连接、已停用”等状态；状态由多个控制条件计算，不能只看上架状态。
4. **应用开发端只选能力和工具**：开发者看到当前项目/workspace 可用的服务及工具，不接触组织凭证；服务更新新增工具时默认不授予调用权。
5. **Claw 保持两条使用路径**：个人 Claw 可使用个人连接；已发布组织智能体按它所属的组织和项目/workspace 授权使用组织连接。用户委托服务在调用前由用户本人完成连接。
6. **首期仍要收窄**：先支持组织共享 Key 的 1–2 个付费服务和个人自带 Key；用户委托 OAuth、细粒度工具策略和精确费用对账作为后续，但服务定义从一开始预留认证模式字段。

## 4. 尚不能从公开资料确认的事

- Aily 文档没有说明预置付费服务的 Key 所有权、费用归属或真实调用审计，不能照搬其默认上架规则。
- WorkBuddy 文档描述了连接/调用次数，未证明可直接得到各供应商的精确账单。
- ChatGPT、Copilot Studio、Claude 的工作空间/组织/环境层级与 AF 不完全相同；AF 的组织和项目/workspace 关系仍应以自身权限与数据模型确认为准。
