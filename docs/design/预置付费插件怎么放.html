预置付费插件怎么放

在线检索、多模态理解这类能力要接第三方付费服务。本文讨论预置这类插件时：接在哪一端、Key 在哪里配、成本由谁承担、能给谁用。

已对齐 已有共识 建议 提出来讨论 待确认 需要拍板或研发核实

核心主张

  • 同一个预置插件，管控端和使用端的广场都上架。
  • 管控端：添加到项目，填组织 Key，项目里的人共用，组织承担成本。发布出去的智能体带组织标记，使用组织 Key。
  • 使用端：添加到自己的 Claw，填个人 Key，只给自己用，个人承担成本。
背景

为什么要做预置付费插件

大背景。平台上的智能体缺少在线检索这类关键能力。这类能力依赖第三方付费服务，免费或开源软件提供不了，必须有人提供 API Key 并承担调用费用。

小背景。现在有两类用户，对付费能力的诉求不一样：

真实用户

企业里的员工。所在企业可能已经统一采购了服务、有公共的 Key；也可能基础设施不健全，没有人负责配置。

内部用户

我们自己的演示环境和测试环境。比如销售给客户演示时，只想给自己的智能体配上 Key，用自己的额度。

我的想法和方案建议

两端都上架，各走一条链路

管控端 · 组织 Key

  1. 在广场找到预置插件，点“添加到项目”
  2. 选择项目（进入该项目的 Workspace）
  3. 填写组织的 Key
  4. 项目里的人和智能体共用；发布出去的智能体带组织标记，使用组织 Key
适合：企业有统一采购或公共资源。

使用端 · 个人 Key

  1. 在广场找到预置插件，点“添加”
  2. 直接配给自己的 Claw，不选项目
  3. 填写自己的 Key
  4. 只有自己能用，其他人看不到也用不了
适合：演示、测试环境；企业没有统一配置、个人有需求。

三个要点对照

要点管控端使用端
在哪里配 管控端广场，“添加到项目”时填写 使用端广场，添加到自己的 Claw 时填写
谁来配 有项目配置权限的人（是否只限管理员） 本人
谁承担成本 组织 个人
给谁用 项目里的人和智能体 只有本人的 Claw
发布后 发布出去的智能体带组织标记，使用组织 Key 个人 Key 不随任何发布带出 建议
理由

为什么两端都需要

付费能力是智能体开箱即用的前提。只放一端，总有一类场景走不通。

只放管控端会怎样

  • 演示、测试环境和没人配置的企业，个人用不上。
  • 个人为自己的需求配 Key，会变成整个项目共用：个人花钱，别人在用。

只放使用端会怎样

  • 企业统一采购的资源没法统一下发，每个人各配一遍。
  • 发布出去的智能体没有组织 Key 可用。
  • 员工各自用 Key，管理和合规都难控。

场景走查

场景走哪端说明
企业统一采购了检索服务管控端在项目里配一次，项目内共用
发布给大家用的智能体管控端带组织标记，使用组织 Key
销售给客户演示使用端只给自己的智能体配，花自己的额度
测试环境使用端各自配置，互不影响
企业没人配置，个人有需求使用端自己付费，只给自己用
边界

需要守住的规则

  • 发布出去的智能体使用组织 Key已对齐

    智能体发布时带组织标记，调用付费插件时用组织 Key，成本记在组织头上。

  • 个人 Key 不随发布带出建议

    个人配的 Key 只作用于本人的 Claw。如果被发布的智能体带出去，所有召唤者都在花这个人的钱，Key 也等于暴露给了别人。

  • Key 不明文展示给他人建议

    项目成员能用组织 Key，但看不到明文；个人 Key 只有本人可见。

  • 调用记录标出 Key 的来源建议

    每次调用标明用的是组织 Key 还是个人 Key，出了费用问题有据可查。

待讨论

还没定的问题

  • 是否两端都预置待确认

    管控端和使用端是否都预置同一个付费插件，还是只放在其中一端？

  • 个人 Claw 能不能直接用项目里配好的插件待确认

    按现在的能力库规则，个人 Claw 只选已发布资源、不选项目。项目里配好的付费插件，个人只能通过召唤已发布的智能体来用。是否需要例外？

  • 管控端要不要“允许成员使用个人 Key”的开关待确认

    部分企业出于数据合规，不希望员工用个人 Key 把企业数据发给第三方服务。可以先默认打开，由企业自行关闭。

  • 首批预置哪些插件待确认

    目前提到的是在线检索、多模态理解两个例子，供应商和计费方式还没定。
