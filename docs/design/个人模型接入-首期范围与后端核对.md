# 个人模型接入：首期范围与后端核对

状态：评审稿；服务商入口已依据官方文档初步核对，最终以研发确认的后端配置和联调结果为准。

## 一、本期范围

- 支持个人添加语言模型。
- 预置服务商：阿里云百炼、MiniMax、DeepSeek、智谱、月之暗面（Kimi）。
- 预置服务商使用产品内配置的默认 OpenAI Chat Completions Base URL；用户填写个人 API Key 和模型 ID，不手填 Base URL。
- 另提供“自定义”方式，用户填写 OpenAI 兼容 Chat Completions Base URL、API Key 和模型 ID。
- 本期不做图片生成模型接入、管理和模型下拉入口。后续如重启该需求，单独确认接口、服务商及运行链路范围。
- API Key 是否按用户隔离、加密保存、不回显明文，以及保存/编辑/删除的行为，仍按模型接入通用需求执行。

### 预置服务商产品规则

1. 预置项固定默认 Base URL；Base URL 不在预置表单显示。
2. 帮助说明标注该服务商本期支持的账号/入口类型。Key 与固定 Base URL 不匹配时，提示用户检查 Key 类型及服务商平台入口。
3. 若某家服务商无法在明确限定的默认入口下仅凭 Key 和模型 ID 调用，则不通过隐藏字段掩盖依赖：应选择增加该服务商必需字段，或将其移出本期预置列表。
4. 服务商文档示例只作为配置核对依据；开发完成后仍需用目标账号和目标模型真实联调。

## 四、后端核对与验收项

1. 为每个预置服务商确认固定 Base URL、Key 类型、地域/账号适用范围、可用模型范围；将最终值固化为服务端服务商配置。
2. 说明不同 Key 类型或入口不匹配时的可识别错误；测试连接失败时提供可操作的提示，不把所有错误都归为“Key 无效”。
3. 确认模型列表接口支持情况。支持时可以提供拉取选择；失败或服务商未实现时允许用户手填准确模型 ID。
4. 测试连接使用 Base URL、Key 和模型 ID 发起一次真实模型调用。任一必填项缺失时阻止发起；测试失败仍允许保存。
5. 上下文长度需明确用户填写值优先、留空回退到 RD 确认的服务商默认上下文预算；后端需确认各服务商的默认预算配置及其进入本地上下文压缩逻辑的方式。
6. 工具调用、图片输入和最大输出长度属于本期目标配置；后端需补齐端到端请求链路并验证配置确实生效。未完成联调前，不得以“配置已保存”替代功能验收。

## 五、竞品/技术模式参考

- Open WebUI 将视觉、工具等能力作为逐模型配置项；LibreChat 也按模型规格记录上下文窗口，并将视觉/工具调用视为模型能力。可借鉴“能力必须和具体模型关联”的管理方式，但不代表 Claw 本期要照搬全部设置。[Open WebUI 模型配置](https://docs.openwebui.com/features/workspace/models/) [LibreChat 自定义模型配置](https://www.librechat.ai/docs/configuration/librechat_yaml/object_structure/custom_endpoint) [LibreChat 能力兼容矩阵](https://www.librechat.ai/docs/compatibility)
- 这些平台的模型能力标记仍需由配置者正确填写；对用户自定义模型而言，产品不应把能力复选框描述成服务商保证或自动检测结果。
