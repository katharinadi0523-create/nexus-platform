# 预置第三方服务治理：轻量改造方案

**日期：** 2026-11-18

**目的：** 在保留现有组件广场、自建插件/MCP管理、Claw消费流程的基础上，为平台预置的第三方付费能力补上工作空间级接入与治理闭环。

## 1. 结论摘要

建议把预置第三方服务配置放在**基础管控的资源管理控制面**，与工作空间、存储卷等资源治理处于同一管理层；不要放进应用开发的自建插件/MCP管理流程。组织负责凭证所有权、策略与费用；项目/workspace 负责资源隔离和实际使用范围。

产品上区分三类对象：

1. **服务目录项**：平台维护的官方服务定义，如在线检索、多模态理解。
2. **服务连接**：按服务认证策略建立组织共享连接、用户委托连接或个人自带连接；连接记录凭证所有者与费用归属。
3. **工作空间授权**：组织明确指定哪些项目/workspace，以及其中哪些成员、应用或智能体可以使用连接及其工具。

现有“插件 / MCP”继续表示技术接入方式；“预置服务”表示平台管理与分发方式。服务可以由 MCP、OpenAPI 或平台代理实现，不为它强行创造新的协议类型。**组织共享 Key 是首批付费服务的目标模式，不是所有第三方服务的统一认证方式。**

本方案不把“发布到本组织/全部组织”用于连接授权，也不要求重做组件广场。组件广场仍负责发现；新增的基础管控入口负责组织连接的配置、启停和工作空间授权；Claw 与智能体消费已授权的服务。

## 2. 调研范围与证据口径

### 2.1 线上现场观察

- 用户提供的 `https://10.252.216.13:30090/af/appforge/plugins` 可访问，页面标题为组件广场，包含“全部组织 / 我的组织”、类型筛选和 MCP / 插件资源卡片。卡片展示发布归属；页面未呈现预置第三方服务的凭证管理或工作空间授权入口。
- 同一环境的“插件管理”路由可以打开；当前选择的测试工作空间显示空状态。这只能说明当前账号和当前工作空间的列表状态，不能据此推断全平台没有插件资源。

- 用户补充的工作空间截图表明：页面按组织筛选工作空间；说明文字将工作空间定义为资源分组和逻辑隔离机制，可授权给用户或用户组。这推翻了本方案初稿把组织与工作空间当作同一边界的假设；仅凭截图不推断数据库中的严格父子关系。
- MCP 管理在另一个域名的浏览器标签中访问时跳转登录，因此未将该标签的页面内容视为同一线上环境的验证结果。

### 2.2 Demo 与设计文档

仓库中的 Claw 插件广场和“我的插件”由本地 Mock 数据驱动。添加、开关和连接检测是前端状态及模拟逻辑，不证明后端已经具备持久化凭证、授权、真实连通性检测、计量或审计能力。仓库里的 Claw 工作台产品文档也是设计稿，不代表线上功能已交付。

本方案把线上现场、用户截图、Demo代码、既有设计文档分别作为不同证据使用；对后台能力不作超出证据的推断。

## 3. 现状判断

### 3.1 目前有的产品基础

- **发现和分发：** 组件广场已覆盖 MCP / OpenAPI 等资源，带有发布者、组织范围和业务分类等信息。
- **自建资源管理：** 插件与 MCP 管理有创建、编辑、调试、上架/下架等生命周期入口。
- **使用端消费：** Claw 已有插件广场和我的插件；现有工作台设计也将其定位为使用平台已发布能力的消费端。
- **基础管控入口：** 工作空间管理、资源池管理和存储卷管理等事项同处基础管控，适合并列新增第三方服务管理入口。

### 3.2 预置服务不能直接套用的地方

- 平台预置服务不由工作空间用户创建，不能依赖“创建插件 → 发布上架”的自建流程。
- “上架”表示目录可发现，“连接成功”表示凭证可用，“已授权”表示某范围可以调用；三者必须分开。
- Key 放在服务定义或普通插件连接参数里，会把共享凭证、工具配置和调用范围耦合在一起。
- 组件发布到组织或全部组织，表达的是资产分发范围；向多个工作空间开通服务，表达的是实例配置及访问授权。
- Claw 面向个人使用，不能默认为其继承当前工作空间的组织凭证。

## 4. 目标产品架构

```text
平台服务目录
  └─ 官方服务定义、技术适配器、工具清单、版本、数据出网和费用说明
       ↓ 管控端选择服务
组织服务连接
  └─ 组织持有的凭证/账号、费用归属、连接状态、最近检查、生命周期
       ↓ 组织管理员明确授权
项目 / workspace 使用范围
  └─ 被授权的空间及其中的成员/应用/智能体；可选择工具范围
       ↓ 运行时按调用上下文解析
Claw / 智能体 / 工作流
  └─ 只引用服务能力，不持有或发布 Key
       ↓
调用记录与状态
  └─ 调用人、调用方、服务、连接来源、工具、结果、可取得的用量
```

### 4.1 组织与工作空间的边界

**组织**是人员身份、管理策略、凭证所有权和费用归属的维度；**项目/workspace** 是资源分组、隔离和授权使用的维度。项目与 workspace 在本文作为同一使用范围的两种称呼；组织与它们并行建模，不再视为同义词。

截图中的组织筛选器用于查看该组织视图下的工作空间；它说明两者有关联，但不足以单独确定所有资源的继承规则。产品应明确记录连接的组织所有者和被授权的工作空间 ID，不依靠页面筛选或名称推断权限。一个组织连接可以显式授权给多个工作空间，未选中的空间不能使用。

### 4.2 管理入口

在基础管控的“平台资源”分组下新增：**外部服务接入**（备选名称：预置服务管理），与工作空间管理、资源池管理、存储卷管理并列。管理员先确认当前组织，再管理该组织持有的连接及其工作空间授权。

页面针对当前组织，提供：

- 服务目录：已配置、待配置、异常、已停用；可浏览平台可提供的官方服务。
- 连接详情：服务商、账号/凭证类型、连接状态、最近检测、创建人、更新时间。
- 配置与连接测试：新增/修改连接，测试成功后再启用；凭证仅写入安全存储。
- 使用范围：明确选择一个或多个项目/workspace；在已授权空间内再控制成员/应用，必要时限制工具范围。
- 使用记录：展示调用人、调用方、服务、工具、连接来源、结果、时间及可获得的调用量。
- 生命周期：停用、重新连接、轮换凭证、撤销连接；影响现有引用时给出提示。

不同权限可拆分授予。组织连接由具备组织级服务配置权限的人管理；工作空间管理员只管理已授权空间内的应用挂载，不因此获得组织 Key 的配置权：

| 权限 | 能做什么 |
|---|---|
| 外部服务查看 | 查看目录、连接状态和授权范围，不看密钥 |
| 连接配置 | 新增或更新凭证、连接测试、轮换和撤销 |
| 工作空间授权 | 指定哪些项目/workspace 可以使用组织连接 |
| 空间内使用管理 | 在已获授权的空间中管理应用/智能体引用，不能扩大连接授权 |
| 用量审计 | 查看调用和用量记录 |
| 平台目录运营 | 维护官方服务定义、版本、准入和下线；属于平台级职责 |

### 4.3 管控端与使用端的职责

**基础管控的外部服务接入**负责“组织开通服务、配置连接、授权工作空间、治理成本和状态”。组织管理员可以把连接授权给一个或多个工作空间；该操作不等于发布组件。

**应用开发端**继续负责开发者创建的 OpenAPI 插件 / MCP 服务。开发者可以在智能体或工作流中选择当前工作空间已获授权的预置服务；未获授权时显示“需组织服务管理员开通”，提供申请入口或管理员配置页跳转，不展示 Key。

**组件广场**保留发现功能。预置服务作为“平台预置”来源展示，卡片明确标记“本工作空间已开通 / 待管理员配置 / 不可用”等状态。上架、下架不再代表某个工作空间的连接状态。

**Claw 使用端**按执行上下文消费授权结果：

- 个人 Claw 的直接插件列表使用个人资源；不因用户属于某组织，就自动获得组织 Key。
- 用户召唤已发布的组织智能体时，由该智能体绑定的组织与项目/workspace 运行上下文检查服务授权；个人 Claw 只看到“该智能体可用的组织能力”和费用归属，不获得凭证。
- 若后续出现项目/workspace 内的 Claw 任务，该任务在明确的空间上下文中使用已授权连接。
- 如果服务要求用户个人 OAuth 授权，用户只对自己的账号完成授权，管理员不能代替用户授予个人账号权限。
- 个人 Key 只属于个人配置，默认不进入工作空间协作调用；组织可在策略中关闭个人凭证用于组织任务。
- Claw 智能体配置中只保存服务引用和所需能力，不复制凭证。

### 4.4 第三方服务的认证模式

| 模式 | 准入与连接 | 使用与费用 |
|---|---|---|
| 组织共享 Key | 组织管理员允许服务并配置组织连接，再授权选定项目/workspace | 授权空间内的智能体调用；费用归组织供应商账号 |
| 用户委托账号 | 组织管理员允许服务，用户本人完成第三方 OAuth/账号授权 | 按用户在第三方系统的权限调用；费用依供应商合同确定 |
| 个人自带 Key | 组织策略允许时，用户在个人 Claw 配置 | 仅本人使用；费用归个人供应商账号 |

服务定义应声明支持哪些模式。运行时根据调用方及其空间上下文选择唯一凭证来源，不在失败后静默切换。竞品证据和各模式适用条件见[专项调研](第三方插件服务供给与管理-竞品调研-2026-11-18.md)。

## 5. 核心对象与状态

### 5.1 最小对象

| 对象 | 关键字段 | 说明 |
|---|---|---|
| 服务定义 `ServiceDefinition` | 服务 ID、平台来源、协议适配器、工具清单、版本、支持的认证模式、数据说明、计费说明、生命周期 | 平台维护；不含客户 Key |
| 组织连接 `OrganizationConnection` | 服务 ID、组织 ID、费用归属、凭证引用、凭证类型、连接状态、更新时间 | 组织持有，可明确授权给多个工作空间 |
| 个人连接 `PersonalConnection` | 服务 ID、用户 ID、凭证引用或 OAuth 授权引用、连接状态 | 用户持有，只在允许的个人或委托场景使用 |
| 工作空间授权 `WorkspaceServiceGrant` | 连接 ID、项目/workspace ID、空间内用户/组/应用/智能体范围、工具范围、状态 | 说明哪一个隔离空间里谁可以做什么 |
| 调用记录 `ServiceInvocation` | 调用者、调用方、服务/工具、连接来源、结果、时间、用量 | 凭证值永不进入普通日志 |

### 5.2 状态分离

| 层 | 状态示例 | 含义 |
|---|---|---|
| 平台目录 | 草稿、已发布、已停止维护 | 服务是否可以被工作空间发现 |
| 组织连接 | 未配置、检测中、已连接、连接异常、已停用 | 组织凭证/账号能否建立有效连接 |
| 工作空间授权 | 未授权、部分授权、已授权、已撤销 | 当前空间及调用方是否有使用权 |

服务上架但未配置凭证时，Claw 不应显示“已启用”；Key 失效不应自动变成下架。管理员列表应继续看得到异常或停用服务，以便治理和恢复。

## 6. 关键用户流程

### 6.1 平台运营上架预置服务

1. 新建官方服务定义，填写服务商、协议适配器、工具清单、鉴权方式、授权范围、数据出网说明、费用模式和版本。
2. 完成供应商与安全准入后发布到目录。
3. 更新工具清单或权限时生成新版本并显示变更摘要；涉及新增写入权限时重新要求组织服务管理员确认。
4. 下线服务时先标记停止新增配置，通知已有使用空间并给出迁移期，再按策略停用。

### 6.2 组织服务管理员开通服务并授权工作空间

1. 进入基础管控 → 平台资源 → 外部服务接入，确认当前组织。
2. 从官方目录选择服务，检查用途、外发数据、权限和供应商费用说明。
3. 选择凭证方式并配置组织连接；首期先支持 API Key / Token 这类服务商 BYOK。
4. 测试连接。失败时保留已配置状态并给出可操作原因；成功后显示连接有效时间。
5. 明确选择可使用的项目/workspace；首期在所选空间内默认全体成员可用。未选中的空间不继承该授权。
6. 启用后，授权的应用开发者和 Claw 用户才能看到可调用状态。

### 6.3 开发者配置智能体

1. 在智能体工具选择器看到当前空间已授权服务。
2. 选择服务及必要工具；界面标明连接来源和费用归属。
3. 服务未开通时显示请求配置入口，不允许开发者自行把工作空间 Key 写入插件参数。
4. 发布智能体时发布服务依赖与权限需求，不发布连接凭证。

### 6.4 Claw 用户调用

1. 个人 Claw 的直接插件列表展示个人可添加的服务及个人连接状态；已发布组织智能体的详情展示其组织能力来源。
2. 召唤组织智能体时，运行时依据其组织与项目/workspace 上下文校验授权并使用组织连接；不要求每位用户重复填 Key。
3. 个人 OAuth 服务由用户本人授权；个人 Key 服务只在个人范围内使用。
4. 调用失败时区分“未授权 / 连接异常 / 服务商额度不足 / 服务已停用”，给出对应管理员或用户动作。

## 7. 与现有模块的关系

| 现有模块 | 继续负责 | 本次如何处理 |
|---|---|---|
| 插件管理 / MCP 管理 | 自建 OpenAPI/MCP 的创建、调试、编辑、启停、发布、下架 | 保留现状；不加入客户凭证治理职责 |
| 组件广场 | 已发布组件和平台预置服务的发现 | 增加来源标签与工作空间可用状态；不配置密钥 |
| 基础管控 | 组织、工作空间、成员权限、资源池、存储卷等控制面 | 在“平台资源”增加外部服务接入入口，与工作空间管理并列 |
| Claw 我的插件 | 个人消费和轻量管理 | 直接插件列表管理个人连接；通过已发布组织智能体使用其获授权的组织能力，不承接组织密钥管理 |
| 智能体 / 工作流编辑 | 组合可调用工具 | 仅允许选择当前空间已授权服务；配置服务引用而非密钥 |
| 服务监控 | 平台服务运行监控 | 后续按需要接入第三方连接可用性和调用统计；首期不改成完整计费系统 |

## 9. 轻量改造范围与分期

### P0：补对象和边界（必须）

- 新增平台服务定义、组织连接、个人连接、工作空间授权四个对象概念；服务定义声明认证模式。
- 在基础管控新增与工作空间管理并列的外部服务接入列表和连接详情入口。
- 分开表示目录状态、连接状态和授权状态。
- 建立凭证安全存储和无明文回显原则；测试连接走后端真实供应商请求。
- Claw / 智能体运行时按当前调用上下文查找授权连接；绝不通过界面/Agent配置传 Key。
- 记录服务、工具、调用方、连接来源和结果。
- 组织凭证默认不外带到个人 Claw 或外部发布范围。

### P1：最小可用闭环

- 首批只接入 1–2 个服务，优先选 API Key 鉴权、工具集稳定、供应商可观测调用量的服务。
- 支持组织配置共享 BYOK 连接并显式授权给选定项目/workspace，同时支持个人 Claw 配置个人自带 Key；支持连接测试、启停、轮换和撤销。
- 组件广场增加“平台预置”和“当前工作空间状态”信息。
- Claw 个人插件显示个人连接状态；组织智能体详情显示组织能力来源；开发者工具选择器只显示空间已授权服务。
- 提供基础调用量和失败原因查询；第三方精确费用以服务商数据可得性为前提，不宣传为已有能力。

### P2：按真实需求扩展

- 选择性授权用户/组/应用及 MCP 工具。
- 批量调整工作空间授权、按空间设置额度，以及按需要建立独立连接。
- 用户委托 OAuth 授权与刷新/撤销、外部服务用量对账、额度/限流策略。
- 出网数据分类、敏感字段控制、供应商准入与更完整的审计。
- 版本升级影响检查、灰度迁移与下线通知。

## 10. 首期不做

- 不重做组件广场的信息架构或自建插件/MCP的上架审批链路。
- 不把预置服务配置伪装成“发布到组织 / 全部组织”。
- 不做平台代收代付、复杂分账或没有供应商计费数据支持的精确成本核算。
- 不让个人 Claw 直接继承组织 Key；召唤已发布组织智能体时按其组织与项目/workspace 授权执行，不做凭证自动回退。
- 不在首期承诺完整 DLP、任意字段级出网策略、所有 OAuth 变体和供应商版本兼容治理。

## 11. 验收标准

1. 有组织连接配置权限的管理员才能新增、替换或撤销组织凭证；查看权限不能读到明文。
2. 组织连接只被明确授权的工作空间调用；未授权的空间和个人 Claw 不能自动获得访问权。
3. 开发者发布的智能体只携带服务依赖，不包含 API Key、OAuth Token 或可还原密钥的配置。
4. 服务上架、连接成功、用户获授权三个状态能分别显示和查询。
5. 连接失效、额度不足、服务停用、用户未授权能给出不同原因和对应处理角色。
6. 管理员撤销连接后，新调用被阻止并记录事件；已引用该服务的智能体能定位到受影响服务。
7. 组件广场的自建插件发布/下架行为不改变预置服务连接或工作空间授权。

## 12. 仍需确认的产品决策

建议按以下默认值推进，除非业务或安全负责人另有决定：

1. 首期费用由配置连接的组织供应商账号直接承担；平台提供调用归属与可得用量，不做代付。
2. 首期组织连接可以授权给多个项目/workspace，但每个目标都须明确选择，不做自动继承。
3. 个人凭证不用于组织协作任务；组织管理员可关闭个人服务用于组织任务的入口。
4. 预置服务是否公开展示给未授权用户：建议可见目录与说明，但“添加/使用”按空间授权状态禁用并说明原因。
5. MCP/OpenAPI 的预置适配实现首期由平台控制，暂不开放用户自行编辑平台官方定义。

## 13. 具体产品落点与默认规则

以下作为可直接进入详设的建议决策。组织与项目/workspace 是两个维度：组织持有共享连接，项目/workspace 获得使用授权。

### 13.1 导航和页面改动

| 位置 | 增加什么 | 谁操作 | 本期改动量 |
|---|---|---|---|
| 基础管控 → 平台资源 | 新增菜单项“外部服务接入”，与工作空间、资源池、存储卷管理并列 | 组织管理员及被授予服务管理权限的人 | 新增一个管理页，不改工作空间列表 |
| 外部服务接入 | 单页两种视图：“可开通服务”“已接入服务”；同一服务详情抽屉承载介绍、配置、授权、调用记录 | 管理员 | 新页和抽屉 |
| 应用开发 → 组件广场 | 官方服务卡片标“平台预置”，展示“当前项目/workspace 可用 / 待组织开通 / 需本人连接”；保留现有 MCP/OpenAPI 分类 | 开发者浏览，管理员可跳转配置 | 卡片字段和按钮分支 |
| 应用开发 → 插件管理 / MCP 管理 | 页面说明改为“管理在此创建的插件/MCP”；平台预置服务不进入自建列表 | 开发者 | 文案与筛选边界 |
| 智能体 / 工作流工具选择器 | 加“平台预置”来源和可用状态，只允许选当前项目/workspace 获授权的工具 | 开发者 | 选择器数据和不可用原因 |
| Claw → 插件广场 / 我的插件 | 官方服务卡片支持“添加到个人 Claw”及个人凭证配置；“我的插件”展示凭证来源、连接状态与费用归属 | 个人用户 | 复用现有列表、详情和配置弹窗 |
| 已发布智能体详情 | 列出其依赖的外部服务、是否可用、费用由谁承担；跨组织使用时显示目标组织是否已接入 | 使用者 | 详情字段 |

### 13.2 管理页应展示与支持的功能

**列表列：** 服务名称与提供方、来源（平台预置）、认证模式、连接状态、已授权项目/workspace 数、近 30 天调用次数、操作。“未开通”服务也在目录中展示，但不能被业务智能体直接调用。

**详情抽屉：**

1. **服务信息：** 用途、工具清单及读/写风险、第三方域名、将发送的数据类型、供应商计费说明、文档与当前版本。
2. **组织连接：** 凭证类型、配置人、最近测试时间、状态、掩码标识；按钮为“配置/更换凭证”“测试连接”“停用”。不提供再次查看明文 Key。
3. **授权范围：** 在当前组织可管理的项目/workspace 列表中多选；显示每个空间的启用状态、引用该服务的智能体数和撤销影响。新增空间默认不获授权。
4. **调用记录：** 时间、工作空间、智能体/用户、工具、结果、凭证来源、调用次数或供应商返回的可得用量；不把估算费用写成精确账单。

**开通流程：**“选择服务”→“确认第三方数据与费用说明”→“配置并测试组织凭证”→“选择项目/workspace”→“启用”。保存未完成时为“待配置”，测试失败时可保存但不可启用。停用或撤销授权前展示受影响的智能体；确认后新调用立即被阻断。

### 13.3 广场与使用端的按钮规则

| 服务状态 | 组件广场中的开发者 | 个人 Claw 用户 |
|---|---|---|
| 平台已上架，组织未开通 | 看服务详情；显示“申请开通”或管理员“去基础管控配置” | 若组织允许个人自带 Key，显示“添加并配置个人 Key”；否则说明不可添加的原因 |
| 组织已连接，当前项目/workspace 未授权 | 显示“申请授权”，不可添加到该空间智能体 | 个人 Claw 不因此继承组织连接 |
| 当前项目/workspace 已授权且连接有效 | “添加到智能体/工作流”，选择具体工具 | 通过已发布的组织智能体使用；个人插件列表仍管理个人连接 |
| 连接失效或停用 | 已引用项保留并显示异常，禁止新调用；提供管理员处理入口 | 显示“连接不可用”，不静默改用个人 Key |

### 13.4 角色与权限默认值

| 角色 | 默认可做 | 不自动获得 |
|---|---|---|
| 平台运营管理员 | 维护官方服务目录、适配器、版本、下线 | 客户组织 Key 的明文 |
| 组织管理员/受委托服务管理员 | 配置组织连接、选择项目/workspace 授权、停用、看组织用量 | 开发者的自建资源编辑权限 |
| 项目/workspace 管理员 | 查看本空间已获授权服务、管理本空间应用引用、申请开通 | 修改组织 Key、把服务授权给其他空间 |
| 应用开发者 | 选择当前空间已授权工具并发布智能体 | 配置组织凭证、扩大授权范围 |
| 普通用户 | 调用已授权服务；在策略允许时配置个人连接 | 查看他人或组织凭证明文 |

首期只需新增“外部服务查看、组织连接管理、工作空间授权管理、用量查看”四个权限点，映射到现有角色。用户是否能在个人 Claw 添加个人连接另设组织策略；它不复用“插件管理-写”权限。

### 13.5 发布与凭证选择规则

智能体保存服务 ID、工具 ID 和所需权限，不保存 Key。运行时按当前执行主体、组织和项目/workspace 授权解析连接。没有匹配连接就明确失败，不按其他用户或组织的 Key 回退。

- **发布给本组织内用户：** 发布智能体可用组织连接，但只有该连接已授权的项目/workspace 运行上下文才能调用；成本由凭证所属组织承担。
- **发布给全部组织：** 发布物只携带服务依赖。目标组织必须开通自己的连接并授权对应空间；否则该工具显示“目标组织未开通”，不能使用发布方的 Key。
- **个人 Claw 添加服务：** 使用本人配置的 Key 或本人完成的 OAuth 授权；个人 Key 不进入组织智能体的发布包，也不替代组织连接。
- **用户委托服务：** 管理员负责准入，用户本人负责连接账号；运行时同时满足组织/空间授权和用户供应商账号权限。

若未来希望发布方为组织外用户承担费用，应另建“赞助调用”授权、预算和风控规则，不与本次普通发布混用。

### 13.6 首批范围与验收

首批建议选择一个在线检索和一个多模态/文档理解服务，前提是均已确认供应商提供可由平台服务端调用的正式接口。每项服务按同一套字段配置，先支持组织共享 Key 和个人自带 Key；OAuth 服务在目录模型中保留认证模式，但不在首批承诺可用。

首批验收必须能完成两条端到端路径：组织管理员开通 → 授权一个空间 → 开发者绑定智能体 → 组织用户调用并看到组织费用归属；个人用户添加 → 配本人 Key → 仅本人 Claw 调用。再验证取消空间授权、Key 失效和发布到全部组织时的阻断行为。
